# 决策记录 — 需求如何演进到定稿

> 本文记录讨论过程、每个决策的理由，以及**被修正过的错误判断**。
> 结论以 `2026-08-25-requirements-locked.md` 为准，本文解释「为什么是这样」。

---

## 1. 起点：用户的原始需求

1. 参与 OKX / X Layer 的 xStocks 流动性激励活动，要求自动化
2. 组哪些 LP 由用户指定，可能同时开 n 个仓位
3. **LP 区间固定上下 0.5%**
4. **出区间就重新平衡：都变成币了就卖掉一半重新组，都变成 U 了就回来继续组**
5. 开发工作交给 codex 执行

---

## 2. 活动规则调研的关键发现

官方口径：**LP 按其在池内产生的交易手续费占比分配奖励，按小时结算**，
奖励以稳定币发放，池必须部署在 Uniswap v2/v3/v4 上，每个合格代币只有一个池。

推论三条（这是全部策略的基础）：

1. 决定收益的是 **in-range 有效流动性份额**，不是本金总额
2. **一旦出界，该小时的份额直接归零**，不是变少 → uptime 是第一优先级
3. 区间宽度是收益的直接杠杆：`资本效率 E(δ) ≈ 2/δ`，±0.5% 约等于 400 倍

用户给的 ±0.5% 因此是合理参数。后续还发现一个反直觉的性质：
出界频率 `N ∝ 1/δ²`，单次已实现 IL `≈ V·δ/4 ∝ δ`，
所以**总摩擦成本 ∝ 1/δ，而奖励份额也 ∝ 1/δ，一阶上互相抵消**。
结论：δ 的具体取值不必纠结，真正决定成败的是**出界到重组完成的延迟**。
这条直接变成了 M7 的性能要求（目标 < 15 秒）。

## 3. 逐条决策与理由

| 决策 | 结论 | 理由 |
|---|---|---|
| D2/D3 出界处理 | 满仓币卖一半、满仓 U **立刻买回一半**，均按现价重组 | 用户明确选择"立刻买回"而非"等价格回来"。等待期间 uptime = 0，奖励直接归零 |
| D2/D3 代码结构 | **必须由同一段代码统一处理，不区分方向** | 读两腿余额 → 算目标 50/50 → 差额一次 swap。无方向分支 = 无特例 bug |
| D4 交易时段 | 标的交易时段**撤出不做市** | 盘中 ±0.5% 会被反复打出界。按 TSLA 级波动估算，盘中平均 8 分钟出界一次，约 48 次/天，摩擦吃穿收益 |
| D14 时段推导 | 撤出窗口 = 该标的**所有上市地**交易时段的**并集** | ASML 是双重上市（阿姆斯特丹主上市 + NASDAQ ADR）。若只按美股时段，"盘前 04:00–09:00 ET"恰恰是欧洲盘主力时段，会在高波动时做市 |
| D5 撤出时持仓 | **全部清成 U**，零敞口 | 逻辑必然：既然不做对冲，唯一能控 delta 的手段就是不持有。若保持 50/50 过盘中，等于裸持一半仓位却不赚任何手续费与激励 |
| D6 Delta 对冲 | **不做** | 用户选择承担多头 delta。对冲模块整个不开发，开发量砍掉一半 |
| D7 出界判定 | **纯链上时间确认，不用外部行情参考价** | 初版设计用「当地股价 × 汇率」算公允价。但本策略只在静默期做市，此时所有股市都收盘，股票行情天然陈旧，新鲜度校验会永久判定不可用 —— 该机制在真正需要它的时段形同虚设。去掉后系统不再依赖任何外部 HTTP |
| D8 运行模式 | 全自动无人值守 + 熔断 + TG 告警 | 做市窗口含周末 48 小时，人盯不住 |
| D9 拆单 | 单笔 ≥ $500 才拆 | 测试期金额极小，滑点可忽略，拆单只会增加延迟 |
| D11 运行环境 | Mac 本机 + launchd，软件层**睡眠容忍** | 不试图阻止睡眠，而是容忍：每次启动/唤醒**先对账链上实际头寸**再决策 |
| D12 测试仓 | < $50 | gas 实测每次再平衡仅 $0.002–0.004，不构成下限。小仓位反而是校准 F2/F3 的理想工具（不扰动池子） |
| D13 开发节奏 | MVP 先上，边跑边补 | Round 1 只剩十余天，但总盘子 $5M、Round 1 仅占 6%，完整系统对准后续轮次 |
| — 奖励领取 | **移出范围，人工处理** | 用户明确表示自己手动领取 |
| — 第一版范围 | **只做静默期** | 用户明确指示 |

## 4. 关键实测数据

| 项 | 实测值 | 用途 |
|---|---|---|
| 池内名义总额 | 约 $244,600 | — |
| 当前 tick 活跃流动性 | 仅相当于 ±0.5% 区间的约 **$2,900** | 说明现有 LP 全铺宽区间，窄区间进去份额极高 |
| $15,000 在 ±0.5% 的份额 | 约 **84%** | 冷门池的错定价确认存在 |
| 池子日手续费总额 | 约 **$25**（由持仓实测反推） | 见 §5 修正记录 |
| 成交频率 | 静默期约 2.2 笔/小时，活跃期约 24.9 笔/小时 | 极度突发，稀疏采样会严重低估 |
| gas 价 | **0.02 gwei**，完整再平衡 $0.002–0.004 | gas 不是约束 |
| 价格冲击模型 | `δ ≈ swap金额 / 577,200` | 滑点建模 |
| 活跃流动性波动 | 2 小时内在 1.25e16 ~ 1.90e16 之间来回 | 份额必须逐条积分，不能取端点 |

**仓位规模的内点最优**：份额是凹函数（饱和），滑点成本是凸函数（随本金平方增长），
所以存在最优本金。按当时数据解出约 $12,800（原时段方案）或 $24,800（真静默窗口方案）。
该结论依赖未证实的预算假设，**F2 落地前不要据此放大仓位**。

## 5. 被修正过的错误判断（重要）

记录在此是为了避免在新环境重蹈覆辙。

1. **把 `positions()` 的手续费字段当实时值**
   `tokensOwed` / `feeGrowthInsideLast` 是上次操作头寸时的快照，不碰头寸永远不变。
   我据此一度得出"67 分钟零成交"的错误结论，差点让整个 F2 校准建立在恒为 0 的读数上。
   正解：对 `NPM.collect` 做 `eth_call`。

2. **用稀疏采样估算成交量**
   每小时采 5 分钟（8.3% 采样率）估出池子日手续费 $8。
   持仓实测反推出真值约 $25，**低估了约 4 倍**。原因是该池交易极度突发。

3. **拿过期读数做对比**
   用一小时前的池价（1770.27）与实时报价比较，误判出 0.65% 的「异常价差」。
   同一时刻重读后完全自洽。**任何跨时间的价格对比都必须同一时刻取数**。

4. **对称 tick 偏移**
   我最初用 `±49.88 tick` 对称计算区间，忽略了 tick 是对数刻度、上下不对称。
   下沿需要 50.13 tick。codex 的实现是对的，我的探针脚本是错的。

5. **把最优时段策略当成常数**
   我一度建议"只做静默窗口"并给出摩擦成本论证，但那个论证隐含了大仓位假设。
   小仓位时激励相对本金极高、摩擦可忽略，最优时段策略实际上是**仓位规模的函数**。

6. **验收深度不足**
   我曾判定 M5 的私钥隔离与广播门控"验收通过"。独立审核证明两者都有洞：
   私钥可从 `__closure__` 读出（我只扫了字符串属性），
   广播门控三层接受真值非布尔（我只看了默认参数值）。
   **教训：安全属性必须用攻击性输入验证，不能靠读代码和看默认值。**

## 6. 明确排除的范围

- 不做 delta 对冲
- 不做跨链桥自动化（资金入场走人工）
- 不做多地址拆分（反女巫风险）
- 不自建 RPC 与索引器
- 不做奖励领取自动化（人工处理）
- MVP 阶段不做份额账本与跨池迁移
