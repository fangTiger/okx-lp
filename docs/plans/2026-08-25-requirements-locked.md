## 2. 时段调度 —— 按上市地并集推导，不套用「美股时段」模板

**规则**：撤出窗口 = 该标的全部上市地交易时段的并集；其余时间做市。
每个池在 `config/pools.yaml` 的 `listings` 字段声明上市地，程序取并集。

### wASMLx（ASML）实例

| 上市地 | 当地时段 | ET |
|---|---|---|
| Euronext Amsterdam（主上市） | 09:00–17:40 CEST | 03:00–11:40 |
| NASDAQ（ADR，1:1） | 09:30–16:00 ET | 09:30–16:00 |

并集 = 03:00–16:00 ET → **撤出**；**16:00–次日 03:00 ET 做市**（11 小时）+ 周末全程。

北京时间（EDT 期间 = ET + 12）：

| 北京时间 | 状态 |
|---|---|
| **04:00 – 15:00** | 做市 |
| 15:00 – 次日 04:00 | 撤出，持 100% U |
| 周末全程 | 做市 |

周计做市时长 = 5×11 + 48 = **103h / 168h ≈ 61%**。

**夏令时必须用时区库处理**（`zoneinfo`，Europe/Amsterdam 与 America/New_York 各自换算），
禁止硬编码北京时间偏移——两地夏令时切换日期不同。

### 事件处理（MVP 范围）

并集时段的副作用：**绝大多数宏观事件自动落在撤出期**（美国 CPI/非农 08:30 ET、
ECB 14:15 CET、欧洲数据 10:00 CET，均在撤出窗口内），无需专门处理。

MVP 只需处理两类：
1. **外汇周日开盘**：周日 17:00 ET（北京周一 05:00），落在做市窗口内。
   EUR/USD 周末跳空会推动 ADR 公允价。默认前后各 30 分钟撤出，可配置。
2. **财报**：手工维护 `config/events.yaml`。ASML 财报周期为 1/4/7/10 月中旬，
   **本次活动期 8/24–9/7 内无 ASML 财报**。但状态机必须支持，
   且注意 ASML 在欧洲时间早上 07:00 CEST（01:00 ET）发布——**落在做市窗口内**。
   规则：财报标的从发布前 4 小时至发布后 18 小时强制 IDLE。
3. 事件文件读取失败 → 按「有事件」处理，撤出（fail-safe）。

## 3. 核心状态机

每池一个独立实例。

```
IDLE ──进入做市时段 且 无事件 且 风控放行──► ENTERING ──► IN_RANGE
                                                            │
                                              池价越过边界   │
                                                            ▼
                                                      OUT_PENDING
                                                       │       │
                                            确认真实   │       │ 判定插针 → 挂起等回归
                                                       ▼       │        （超时强制重组）
                                                  REBALANCING ◄┘
                                                       │
                                                       ▼
                                                   IN_RANGE
IN_RANGE ──离开做市时段 / 事件 / 熔断──► EXITING（burn+全换 U）──► IDLE
```

**REBALANCING 不区分方向**：读当前两腿余额 → 算目标 50/50 → 差额一次 swap。
D2 与 D3 是同一段代码。

**交易顺序强制为 `burn → collect → swap → mint`**：必须先撤流动性再换，
否则自己的 swap 会打到自己的 LP 上。

## 4. 出界判定与防插针

参考价按优先级降级：

| 优先级 | 来源 | 可用时段 |
|---|---|---|
| 1 | 其他场所的同资产实时价（Solana 池 / Gate / Kraken） | 7×24 |
| 2 | 标的股票实时报价 | 各上市地盘中（我们此时不做市） |
| 3 | 无参考价 → 「价格持续位于界外 ≥ 60 秒」 | 兜底 |

```
链上价出界时：
  参考价 R 不可用 → 等 60s，仍在界外则确认
  |链上价 - R| / R ≤ deviation_threshold(0.4%) → 确认真实移动，立即重组
  否则 → 判定插针，挂起，每 5s 复检；超过 pin_timeout(10min) 强制重组
```

## 6. 睡眠容忍（D11 的硬性要求）

Mac 会睡眠、断网、系统更新。**不试图阻止睡眠，而是容忍它**：

1. 每次启动与每次唤醒，**先对账链上实际头寸**（读 NPM 的 position），
   再与本地状态比对，以链上为准，然后才允许决策。
2. 心跳写入 `log/heartbeat`；超过 15 分钟无心跳 → 唤醒后首条 TG 告警说明失联时长。
3. 系统层兜底（部署脚本提供，非程序职责）：
   `caffeinate -dimsu` 包裹进程；`sudo pmset repeat wakeorpoweron MTWRFSU 03:45:00`
   在做市窗口开始前唤醒。
4. 风险可控的依据：做市窗口内期望出界间隔约 31 小时，睡眠 1–2 小时大概率无事发生。
   但**必须对账**，不得假设「睡前状态 = 醒后状态」。

## 7. MVP 范围划分

### MVP（Round 1 内上线）
- 只读观测器（**最优先，今天就跑**，每天延后就少一天基线数据）
- 时段状态机（上市地并集 + 事件 yaml）
- 建仓 / 出界检测 + 参考价交叉验证 / 重组 / 撤出
- 风控：dry-run 闸门、HALT 文件、再平衡次数上限、滑点上限、交易前模拟、地址白名单
- 睡眠容忍对账
- TG 告警 + 心跳
- 逐笔记录：触发原因、出界方向、空窗时长、swap 成交价与滑点、已实现盈亏

### 后置（Round 2 前补）
- 奖励归因与 NAV 快照
- 奖励密度监控、跨池迁移、退出决策
- 最优仓位求解器（收益凹 / 成本凸的内点最优）
- 合伙份额账本
- 财报日历 API（MVP 用手工 yaml）

## 8. 风控硬闸门（策略层无权覆盖）

1. F2/F3（奖励分配规则、手续费口径）未校准 → 单池投入不超过 `probe_capital_usd`
2. `log/HALT` 存在 → 拒绝一切写链操作
3. 事件窗口 → 强制 IDLE；事件文件读取失败按有事件处理
4. 单日净值回撤 > 3% → 全部撤出并停止开新仓
5. 每池每日再平衡次数触顶（默认 30）→ 该池转 IDLE
6. 交易发送前必须 `eth_call` 模拟，回滚即中止
7. 合约与代币地址白名单，非白名单一律拒签
8. 启动/唤醒未完成链上对账前，禁止任何决策

## 9. 明确不做

不做 delta 对冲、不做跨链桥自动化、不做多地址拆分、不自建 RPC 与索引器、
MVP 阶段不做份额账本与跨池迁移。
